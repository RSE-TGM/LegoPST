LegoPST — annotated documentation index

LegoPST documentation has piled up over thirty years: Word manuals and hypertext help from the '90s, porting notes, and the Markdown documents written recently next to the code they describe. This page lines them up by subject and says when you need each one. Several documents are written in Italian; the index tells you what is inside before you open them.

How to read an entry. The badges give format and status: md Markdown text — a browser shows it as plain text, the editor renders it; html browsable hypertext; doc Word (needs LibreOffice); pdf; txt; legacy period material, good as a reference but not kept up to date; working copy only file in .gitignore: whoever clones the repository does not get it.

1. General orientation 5 documents

To read before touching anything: what LegoPST is, how the environment is set up, how it is built.

Project overview mdREADME.md

Scope: architecture, core components, libraries, configuration system, glossary of the pieces a simulator is made of. Also installation (Docker container or Fedora 41), creating the work area from the demo, building from source and an index of the documentation.

When you need it: it is the front door. If you do not know what a task, a model, the scheduler or the point SHM are, start here; it is also what you read when installing LegoPST on a new machine.

Preparing the environment mdEnvironment_setup.md

Scope: dependencies and compilers, directory conventions, threading and IPC.

When you need it: installing on a new machine, or when a build fails because a library is missing.

Building, and handling simulators mddocs/BUILD.md

Scope: make -f Makefile.mk, the Docker image as a separate target (make docker), versioning, the ksetsim/ksims commands that pick the active simulator, creasim, kDiffS01.

When you need it: every time you build. It also holds the most expensive trap in the project: without source .profile_legoroot the include paths stay empty and the build fails in a way that does not say why.

Code conventions mdworking copy only CONVENTIONS.md

Scope: the style and the conventions to follow when writing code in this repository.

When you need it: before adding code. Careful: it is in .gitignore (Claude debug group), so it lives only in this working copy: whoever clones the repository will not find it.

Map and traps (for AI assistants) mdworking copy only CLAUDE.md

Scope: index of the documents and list of the operational traps (source the profile, ksh88 in the kbin scripts, killsim instead of pkill, the test alias, ASCII only in Tk scripts…).

When you need it: it is written for Claude Code, but the traps section is the densest list of things that waste time. Not tracked in git either.

2. Configuring and running a simulator 4 documents

From how a simulator is composed to the commands that start and govern it.

al_sim.conf — how it is written mddocs/AL_SIM_CONF.md

Scope: the file that composes a simulator: every option with its default, the task table (types P/R/N, directory, step) and the filespec column, which decides what MMI pages belong to which control task.

When you need it: creating a new simulator, adding or removing a task, or when pages do not show up in the MMI. It closes with the typical mistakes and the message that gives each one away.

The lg* commands — user guide mddocs/COMANDI_LG.md

Scope: the commands starting with lg: entering the environment (lgini, lggo), the container (lgdock), the CAD (lgpc), the HMIs (lghmi), realigning the simulator (lgupsim), the work area (lgswitch), the version (lgversion), the terminal chosen by the user (lgterm, and how to pick it), the Linux/Windows converters and FMU co-simulation.

When you need it: it is the starting point for anyone using LegoPST. Every entry has a short description and, where one exists, a pointer to the specialised document. None of these commands exists without source .profile_legoroot.

The kprocedure commands mdkbin/README.md

Scope: the 192 k* commands that run a simulator: start, stop, compile, archive, connections, MMI, statistics.

When you need it: to find out which command does what. Remember that these tools do cd $KSIM and ignore the current directory: you pick the simulator first, with ksetsim.

kbin — command reference (hypertext) htmlkbin/kbin-riferimento-comandi-LegoPST.html

Scope: the same commands as a browsable page.

When you need it: a quick look in the browser, without opening the editor.

Master Monitor (new_monit, the desk) mdAlg_rt/net_simula/new_monit/README.md

Scope: the main monitor of a session: options persisted in .bi_options, User Programs (up to 8 shell commands launchable from the menu) and how Save/Load behave in the optionSet editor.

When you need it: to hang your own script on the desk buttons, or when session options do not get saved the way you expect.

3. CAD and modelling — legopc 6 documents

Drawing the models: diagrams, module libraries, topology, and the selector that opens the operating interfaces.

legopc — the graphical CAD mdAlg_legopc/README.md

Scope: module libraries, the .i5/.tom/.remap/.lstyle formats, remark and backgrounds, the operator elements of a page (faceplate buttons and set value), the variable shown under a block (double click in Show Value), the View menu, the model dialogs (Open, Save, Save As, Include, Delete Model), PDF/PNG export (in draw2gr too), Command Mode, Set Sim path, engineering units and the external programs (editor, viewers, terminal).

When you need it: drawing or changing a diagram, preparing a page to be used as an operator panel during the simulation, and to work out which file comes out of which step of the chain.

Background elements (bgimage) mdAlg_legopc/BACKGROUND_ELEMENTS.md

Scope: step-by-step recipe to add background graphics to a diagram.

When you need it: it is a procedure, not an explanation: you follow it while you work.

lghmi — HMI and faceplate selector mdAlg_legopc/LGHMI.md

Scope: the selector that opens the process pages (draw2gr) and the command faceplates (xstaz), the button that starts the MMI, starting the simulation (net_startup) and the realignments (kUpSim, kCompile), opening models in the CAD (Tools → Edit model and the Edit menu of the HMIs), the current simulator (File → Current simulator, which follows the directory you are looking at), a terminal in the simulator directory (Tools → Terminal), switching work area (File → Work area, through lgswitch) and the format of the S01 file that describes a composed simulator.

When you need it: to open the interfaces of a simulator without remembering the commands by hand, to move from one work area to another without leaving processes stranded between the two, and as the reference on the S01 format.

Alg_legopc release notes txtlegacy Alg_legopc/Readme.txt

Scope: notes on the Alg_legopc-2006ASP1_RHE4 release.

When you need it: archaeology on what changed in that version.

LegoPc 5.0 release notes txtlegacy Alg_legopc/install/relnotes.txt

Scope: release notes of version 5.0 of the CAD.

When you need it: historical reference on the features introduced then.

Installation environment variables txtAlg_legopc/install/vardef.txt

Scope: an example of how the variables are defined (LG_BASE and the rest).

When you need it: as a comparison, when the CAD environment does not behave as expected.

4. Run time: trends, values, faceplates 9 documents

What you use with the simulator running: watching the curves, reading and writing the points, commanding the actuators.

graphics — trend viewer mdAlg_rt/grafica/graphics/README.md

Scope: the program that draws the curves reading the circular file f22.

When you need it: to watch how the recorded variables move. Mind the near-homonym: graphics (circular f22) and grafics without the h (sequential f22, used by drift/crealg5) are two binaries with incompatible formats.

Binary format of f22circ.dat mdAlg_rt/grafica/graphics/f22circ_format.md

Scope: the layout of the circular file: header, records, indexes.

When you need it: writing a program that reads or produces that data, or when the plots come out at zero and you have to look inside the file.

Structure of f22.dat, the Fortran side txtdoc/struttura_f22_fortran.txt

Scope: how the Fortran (proc/lg5) writes the samples file.

When you need it: the counterpart of the document above, from the side of whoever produces the data rather than whoever reads it.

viewval — reading and writing points mdAlg_rt/net_simula/viewval/README.md

Scope: inspecting shared memory: picking variables, interactive mode with value editing, a log of what was written. It is also the engine behind the set value elements of a page (viewval -f).

When you need it: quick diagnosis — see what a variable is worth, or force it by hand without going through a graphical interface.

Command faceplates: compstaz and xstaz mdAlg_rt/grafica/xstaz/README.md

Scope: the faceplate chain: r01.dat (source) compiled by compstaz into r02.dat, displayed by xstaz; how a page gets opened (net_monit, lghmi, stazpag, the faceplate buttons on a diagram).

When you need it: to understand the architecture before touching the files.

lgmkstaz — the graphical faceplate builder mdAlg_legopc/LGMKSTAZ.md

Scope: building r01.dat on screen instead of by hand: the grid with the origin at the bottom left, the library of the 54 station types, drag, copy and paste, the property panel wired to the model's real variables, "compile and check" with the real compstaz on a scratch copy, and the preview in the real xstaz.

When you need it: whenever you build or change a faceplate page. Read the HOWTO below for the file format the builder writes.

Station catalogue and sprites mdAlg_rt/grafica/xstaz/catalogo/README.md

Scope: the read-only r01.dat holding all 54 station types with their names, real screen captures of its pages, and the per-type PNG sprites that lgmkstaz draws with — plus how to regenerate the whole chain.

When you need it: to see what a station type looks like before using it, or after changing new_staz[] in newstaz.h.

Faceplate HOWTO — the working manual mdAlg_rt/grafica/xstaz/HOWTO_faceplate.md

Scope: the longest document in the project (over 2000 lines): the format of r01.dat line by line, a catalogue of all 54 stations with their code, the full life cycle and a checklist.

When you need it: every time you configure a faceplate. It is written to be used while working, with examples you can copy.

Visual catalogue of the station types mdAlg_rt/grafica/xstaz/catalogo/README.md

Scope: a picture of every faceplate type with its name underneath, plus the r01.dat that generates them.

When you need it: to pick a station type by looking at it, instead of guessing from the name. The same pictures are embedded in the HOWTO.

5. MMI — the SCADA-like interface 3 documents

The animated mimic pages: a world with files, directories and conventions of its own, separate from the CAD and from the process pages.

Alg_mmi — Context, pages, generation chain mdAlg_mmi/README.md

Scope: the Context.ctx file as the single source of truth, how mmi finds the pages at run time and how the configurator finds them (differently), the .pag → .rtf/.bkg life cycle, the three page generators (config, convstaz, mkstaz/kcreastaz) and the kMakeGlobpages/kGlobContext/kMmiConfig/kMmi chain.

When you need it: when a page does not show up, when the MMI does not start, or when a simulator is moved to another machine. It explains the nastiest block of all: on a single machine kMmi configures the client/SCADA route and the MMI waits in timeout for a server that does not exist.

Connecting ports and variables in config mdAlg_mmi/config/CONNESSIONI.md

Scope: how diagrams are wired to each other in the page editor. In Italian.

When you need it: while drawing or fixing a control page.

Copy and paste in the text fields of config mdAlg_mmi/config/COPIA_INCOLLA.md

Scope: the (not obvious, Motif) behaviour of copy and paste in the editor. In Italian.

When you need it: a short, practical note, to be read once.

6. FMU and co-simulation 2 documents

Exporting a LegoPST task as a standard FMU and running it together with other simulators.

lg_fmu — build, bundle, HMI, diagnostics mdAlg_rt/lg_fmu/USAGE.md

Scope: the complete guide (over 900 lines): how an FMU is built from a task, how a self-contained bundle is packed, how the HMI is attached (with the faceplate buttons and the r02.dat compiled for the task), how to diagnose it.

When you need it: for anything about FMUs. One working note: testing a bundle from a shell with the LegoPST profile sourced proves nothing, because the LG_* variables leak in and hide what the bundle is missing; use env -i.

Manual of the lg_cosim master mdAlg_rt/lg_fmu/lg_cosim/lg_cosim_manual.md

Scope: the co-simulation master: configuration file, use of third-party standard FMUs, known limits.

When you need it: when several FMUs are made to talk to each other, each with its own key and its own step.

7. Legacy hypertext help 2 trees, ~330 pages

Two HTML trees from the '90s and 2000s, produced from Word documents and still browsable. They are the most complete source on the theory and on the module library, areas the recent documentation does not cover.

Alg_help — general simulator manual htmllegacy Alg_help/html/alterlego.htm

Scope: the general index (titled Puertollano Dynamic Simulator Project) leading to six areas: Legocad, Regommi, Executive, MMI, Scada, AlgDB.

When you need it: this is the entry point to open in a browser. Sub-trees:

  • legocad/ — 9 pages: documentation, elementary data, glossary, graphics, libraries, simulation, steady state, topology
  • legocad/lib_proc/ — 53 pages: the process module library (adiv, aext, amme, attu…), one sheet per module
  • legocad/models/ — 16 pages on the models
  • legocad/lpteoria/ — 16 pages of theory (thermal hydraulics, methods)
  • istr_sta/ — 11 pages on the instructor station
  • legommi/ 6, regommi/ 7, scada/ 1
  • Alg_help/rtf/ — the 20 RTF sources of those same pages
Online help of the legopc CAD htmllegacy Alg_legopc/Alg_legopc_help/index.htm

Scope: 218 pages of CAD guide: activities, introduction, main features, library handling, modules, legosim.

When you need it: it is the help called by ? → Help inside legopc.tix, but it also opens straight in a browser. The 33 original Java applets were replaced by links, so today it works without plugins.

10. Working notes and maintenance tools 6 documents

Notes written during specific jobs. They are not manuals: they are the record of what was done and why.

Scope: the hunt for float parameters clashing with the prototype, a silent defect typical of K&R C; it includes the scanner that finds them.

When you need it: touching old functions with no prototype, or when a value arrives wrong for no apparent reason.

Converting sources Linux → Windows mdutil2025/lglinux2win.md

Scope: the lglinux2win.py script: what it converts and with what limits.

When you need it: keeping the Windows branch of the code aligned.

Converting sources Windows → Linux mdutil2025/lgwin2linux.md

When you need it: bringing back to Linux the changes made on the Windows branch.

Adding the casts to set_something mdutil2025/add_cast_v6_readme.md — and add_cast.md

Scope: the awk scripts that add explicit casts to the variadic calls. add_cast.md is the raw transcript of the working session; the _v6_readme is the tidy version.

When you need it: re-running or adapting that mass transformation. Start from the _v6_readme.

Using get/set_something_val mdAlgLib/libutilx/usare_get_set_something_val.md

Scope: notes on the variants that handle the types correctly. In Italian.

When you need it: a working note in narrative form, to be read with the header at hand.

X resources example mdutil2025/risorse/Readme.md

Scope: a sample X resources file and the role of XAPPLRESDIR.

When you need it: when a Motif application does not pick up the colours or the fonts you expect.

11. Documentation outside the repository 7 documents

These live next to the Fortran sources of the modules, in ~/legocad/libut_reg/libreg/: they are not in the LegoPST repository but they are very much part of the documentation you work with. In Italian.

Set point programmers — comparison guide md~/legocad/libut_reg/libreg/programmatori_setpoint.md

Scope: a comparison table of the past, pmsp, pmss, pmst, pmia modules: inputs, outputs, operating modes.

When you need it: to choose which module to use in a control scheme. It is the first of the seven to read.

Sheets of the individual modules md~/legocad/libut_reg/libreg/{past,pmsp,pmss,pmst,pmia}.md

Scope: one sheet per module, all following the same ten-section pattern: variables, parameters, internal logic, flow chart, tuning examples.

When you need it: configuring that module in a scheme, to know exactly what each input does.

Migrating from past to pmss md~/legocad/libut_reg/libreg/migrazione_past_pmss.md

Scope: a map of the correspondences between the two modules, input by input.

When you need it: replacing an existing past in a scheme that already works, without losing pieces along the way.

12. What is not indexed here

For completeness, the files that look like documentation but are not, or that have nothing to do with LegoPST.

  • .aider/*.md and .aider.chat.history.md — the memory of an AI assistant, not project documentation
  • Alg_legopc/Alg_legopc_help/_vti_* — 218 FrontPage metadata files, service copies of the help pages
  • AlgLib/dcethreads_lib_no/**/readme — third-party READMEs (DCE RPC)
  • kdefaults/scada/start_txt/*.txt — SCADA startup data, not text
  • the FMU bundles under Alg_rt/lg_fmu/lg_cosim/example/*_bundle/ — they hold copies of documentation already indexed here
Where to put a new document. The rule followed so far: documentation lives next to the code it describes (Alg_mmi/README.md, Alg_rt/grafica/xstaz/HOWTO_faceplate.md), and goes in docs/ only when it concerns the whole project (BUILD.md, AL_SIM_CONF.md). When you add one, add a row to the table in CLAUDE.md and an entry here.
A static page: double click opens it, no server needed. The links are relative to the root of the repository, so follow them with the file kept where it is (LegoPST/DOCUMENTATION_INDEX.html). In a browser .md files show up as plain text; for the rendered version open them in the editor.
